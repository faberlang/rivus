## Summary

Port `radix-mir-stepper` — Radix's in-process MIR interpreter (`faber run`'s engine) — to Faber under `rivus/src/mir-stepper/`, mirroring the crate file-for-file per the STRUCTURE.md naming rule (`radix-mir-stepper` → `src/mir-stepper/`; `kernel/` and `conversio/` nest under it). The product goal: a working scalar-core interpreter whose `StepperDispatchStatus` / `CapabilityGap` classification and runtime reject behavior reproduce Radix's EXACTLY — reject agreement is the honesty floor (CAMPAIGN metric 2, hard rule 5). The tensor/GPU/sparse/interval lane is deferred per scope lock L2: the Value carriers and enum shape stay for parity, but the dispatch rejects with Radix's shape vocabulary under a documented Defer bucket.

## Port notes / frictions

1. **The big match.** `eval_runtime_call` + `eval_collection` (~65 match arms) and `convert_to_target` are the core. Faber `match` over `union` mirrors Rust exhaustiveness; the family ledger's exhaustiveness is the compile-time guard — port it as a match over `MirRuntimeAbiFamily` and keep a table test (proba) pinning all 14 rows.
2. **Multi-file impl in Rust vs one class in Faber.** Radix spreads `impl Stepper` across lib.rs/runtime.rs/conversio.rs/conversio/{scalar,aggregate}.rs; Value methods across value.rs. If Faber classes cannot span files, model Stepper methods in `runtime.fab` and convert the cross-file evaluators (collection ops, conversio targets, projections) into free functions that take the interpreter state as an argument — identifiers stay 1:1. Same for `Value` methods (`as_bool`/`as_index`/`display`/`to_key`) → free functions over the union. **Verify Faber's class/impl model first; this decides the file anatomy.**
3. **Cycles.** `StepperError` + `stepper_issue` + the `FaberScript unsupported` prefix move to `value.fab` so every other module imports one leaf; consolum + `dispatch_kernel` fold into `host.fab`; conversio dispatcher lives in scalar.fab with aggregate.fab importing one-way. Import surface: `import from "rivus:mir-stepper/value"` etc.
4. **Shared mutation cells.** `Rc<RefCell<…>>` (Array/Map/Struct/…/Tensor) has no direct Rc in Faber; L4 arena-ID says: Value collection variants carry a **cell id** into a cell store owned by the interpreter state, with the borrow discipline (one writer, read-after-write) reproduced. Open decision to confirm against the en stdlib (`cella`-style ref type if present).
5. **Ordered tabula vs FxHashMap.** Radix maps/sets are `FxHashMap`/`FxHashSet` (deterministic per program, layout-order, not insertion-order); rivus uses ordered `tabula<K,V>`. Map display (`display_tabula_map`) and set operations must match radix output on the corpus — verify during parity wiring; do not reorder radix semantics to fit tabula.
6. **Runtime-contract constants (decision).** No `rivus/src/runtime-contract/` directory: per STRUCTURE.md it appears only if a real boundary emerges, and no cross-crate consumer exists in rivus. `display_*` + `Instans`/`InstansPraecisio` fold into `mir-stepper` (display helpers in value.fab, instans conversions in conversio/scalar.fab, toml kernel imports them from value.fab). The `tensor` constants (ERR_ACCIPE_INVALID_INDEX, ERR_CREA_INVALID_SHAPE, ERR_ELEMENT_COUNT_OVERFLOW, ERR_FORMA_*, ERR_MATMUL_*, ERR_PONDE_INVALID_INDEX) are only read by the deferred tensor arms → **not ported now**; revisit when the lane ships.
7. **Default-reject host.** The `Host` seam with fail-closed defaults is the security gate (SECURITY.md posture 1). `StdioHost`-equivalent enables only stdout/stdin/exit; file/subprocess/env/args/random stay opt-in through the seam. `abort`/`exit` are never-returning.
8. **Tensor lane (L2, decision).** Ledger rows match Radix EXACTLY (RuntimeGradient stays Implement in the ledger). The *implementation* of the deferred lane (tensor/sparse/interval collection ops, gradient handles, Tensor/Vector/Matrix unops) rejects at the dispatch arms with the radix shape vocabulary (`FaberScript unsupported: intrinsic Collection(<op>)`, `intrinsic <Variant>`), tracked in a **Defer bucket** extension of the classifier (per-op gap pass over MirCollectionOp → `UnsupportedMirShape`, slug `unsupported-mir-shape`). Documented deviation: tensor corpus files are excluded from the parity set until the lane ships — flagged, not hidden.
9. **aleator determinism.** `semina` seeds `StdRng` (rand crate, ChaCha12). Seeded-sequence parity requires reproducing the generator; unseeded (entropy) paths and `octetos`/`uuid` need an OS entropy source — excluded from determinism parity, seeded sequences are not.
10. **No toml/serde_json/regex crates.** toml/json kernels and the Regex value carrier (pattern identity) need Faber-side implementations; Regex is a literal carrier (`runtime_regex_pattern` identity), so a textus-backed carrier + flags re-emit (`regex_pattern` flag filter `i m s u U x`) may suffice at first.
11. **Error-text fidelity.** `StepperError.message`/`issue`/`span` are the reject-agreement surface (`stepper_issue` slugifier, `numerus overflow`, `numerus division failed`, `... conversion failed`/`out of range` recoverability, `modular_division_by_zero`). Port verbatim.

## Done-when

1. All `rivus/src/mir-stepper/` files above exist with en identifiers 1:1 and import via `rivus:mir-stepper/<path>`; no inlining; green `faber check` on the module set.
2. `value.fab` implements `Value`, `MapKey`, width-checked + modular-word arithmetic, comparisons/equality, `format_template`, and display — `numerus overflow` / `numerus division failed` semantics match radix (proba/unit tests on overflow boundaries and mixed carriers).
3. `runtime.fab` implements the Stepper frame loop and the intrinsic/collection dispatch; scalar collection arms run; deferred-lane arms reject with the radix shape vocabulary; unsupported intrinsics produce `FaberScript unsupported: intrinsic <Variant>` with the exact `stepper_issue` slug.
4. `capability.fab` reproduces the exhaustive 14-family `stepper_dispatch_status` ledger EXACTLY (12 Implement / 1 HostDelegate / 2 IntentionalReject), plus the `Defer` bucket extension and `classify_stepper_lowerability` with all documented gap shapes and slugs.
5. `host.fab` Host seam default-rejects every capability; `StdioHost`-equivalent + `BufferHost`-equivalent behave as radix hosts (scribe routing, write_stdout_raw buffering, exit/abort).
6. Kernels: all solum/processus/toml/json/aleator verbs dispatch; unsupported verbs reject as `kernel <module> verb \`<verb>\``; `aleator.semina` seeded sequence reproduces radix's StdRng output.
7. Conversio: target-directed `convert_to_target` incl. width-honoring textus↦numerus<W>, dynamic-source `MissingFieldPolicy`, lazy recovery, and `struct_wire_field_key` — conversion-failure messages end in ` conversion failed`/` conversion out of range` and route to `ReturnError` with a textus-compatible error type.
8. **Reject agreement wired (the floor):** a parity harness (`scripts/run-parity.fab`) compares rivus vs radix `run_source` (StdioHost-equivalent) — dispatch status + `CapabilityGap` classification agree on the expected-reject set (100%), and stdout + exit code agree on the scalar runnable corpus; mismatch = defect.

## Out of scope

- Tensor/GPU lane implementation: TensorValue/GradientStorage/Sparse/Interval dispatch, gradient handles, tensor unops/collection ops, tensor error constants — deferred (L2), reject-matching only.
- MIR codegen backends, borrow analysis, kernel-namespace/device-program surfaces (dropped per CAMPAIGN).
- Driver orchestration (`run_source`/`run_analyzed`, `RunSourceError`, session/frontmatter) — the driver goal owns analyze/lower wiring; this goal provides the stepper-side entry (`run_entry` equivalent) and parity harness.
- Provider bridges beyond the kernel surface (`provider` on Host stays reject unless a host opts in).
